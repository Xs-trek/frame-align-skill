# 页面契约

> 实现状态：页面模板与自动回传脚本尚未实现。在它们就绪之前，由你按本契约自行生成单文件 HTML，并使用粘贴回传。

本文件规定页面承载什么、标记有哪些、回传怎么走。视觉上怎么呈现由你决定。

## 为什么是页面

一是减轻用户的打字负担。能点选的不让他打字；点选表达不了的，旁边就有地方写。

二是页面的形状本身在起过滤作用。不同模型的输出风格差别很大，用"请简洁"这样的话去约束，效果不稳定。但一张卡片只有一两句话的位置，冗长就放不进去；需要他定的事单独成区，混在说明里就摆不上去。

## 页面上有什么

页面提供下面这些位置，有内容的才出现。所以页面随框架长大，首页最轻。

始终有：

1. **目标锚点。** 用户的原话。他可以改。
2. **本轮在做什么。** 一两句：从他上一轮的反馈里读到了什么、因此改了什么，这一轮打算做什么。
3. **本轮内容**，按"要他做什么"分成三区，空的区不出现：
   - 需要你定的。排在最前。
   - 我告诉你的。你的看法、灵感、事实、解释。
   - 我先定了的。一张短清单。
4. **整体文本框。** 供他写任何没被覆盖的东西：疑问、不满、想换的方向。
5. **整轮反馈。** 一排可不选的选项，见下文。
6. **下一步。** 再来一轮；灵感够了；框架成立。

有了内容才出现：

- **你的理解。** 完整的一段，出现在开局、方向发生变化、出口之前。他可以直接改写它。
- **框架现状。** 框架有了节点之后出现。每个节点显示当前内容和状态，带备注框和"重开"；依据已变的标出来。
- **收起的内容的入口。** 本轮没有展开的提议。
- **观察记录和日志的入口。** 观察记录可编辑。

首页的内容见主文件"开局"第 4 步。

## 卡片

每张卡必备三样：正文、适用的标记、备注框。

按需出现的：来源只在事实上显示；选项与推荐只在需要他定的事上显示；所属节点在框架有了节点之后显示。

不显示动作和性质的名称。他不需要知道一条内容在你的分类里叫什么，只需要知道要他做什么。

正文一两句。更长的说明收进卡片的展开部分。

## 标记

每张卡只放适用的标记。按钮上的文字跟随用户的语言，也可以按语境改写；写入状态和回传时对应到括号里的键。不标记是允许的，表示他对这条暂无意见。

| 卡片 | 可用标记 | 标记后的结果 |
|---|---|---|
| 灵感（发散时的提议） | 留着（`keep`）、不要（`drop`）、多来点（`more`） | 留着：成为候选节点，状态为待定。多来点：下一轮沿这个方向 |
| 建议 | 接受（`accept`）、不接受（`reject`）、解释（`explain`）、去核实（`verify`） | 接受：并入框架。不接受：不并入，日志记一行 |
| 需要你定的事 | 各个选项（`choose`）、解释（`explain`）、去核实（`verify`） | 选中任一项：对应节点已确认 |
| 事实 | 不对（`wrong`）、去核实（`verify`）、解释（`explain`） | 复核后报告。复核后仍各执一词：有分歧 |
| 解释 | 还是没懂（`explain`） | 换一种说法再讲 |
| 我先定了的 | 我来定（`take_over`） | 转成需要你定的事 |
| 框架现状里的节点 | 重开（`reopen`） | 已确认变回待定，记入日志 |

每张卡和每个节点都带备注框。标记只负责便宜的决定，真正改变方向的内容多半出现在备注里。

## 整轮反馈

放在页面底部，可多选，可不选。选了就记入观察记录，并据此调整下一轮。

| 选项 | 键 | 下一轮怎么调 |
|---|---|---|
| 输出太多 | `too_much` | 减量，收起更多，正文更短 |
| 输出太少 | `too_little` | 多展开几条，讲得细一些 |
| 太难懂 | `too_hard` | 换说法，少用术语，把选择讲成后果 |
| 跑偏了 | `off_track` | 对照锚点，告诉他你认为偏在哪，按他的备注拉回 |
| 进度太慢 | `too_slow` | 每轮推进更多：多替他定小事，把相关的决定合并，少发散，主动建议收敛 |
| 进度太快 | `too_fast` | 放慢：少并入，回到他还没想清的地方，多给解释 |

## 技术约束

- 单个 HTML 文件，样式和脚本内联，不依赖外部资源。用户可能离线，页面也要能直接双击打开。
- UTF-8 编码，页面带 `<meta charset="utf-8">`。
- 页面语言跟随用户使用的语言。
- 生成页面时把当轮状态嵌进页面，不要让页面去读本地文件，直接打开的页面读不了。
- 存到 `.frame-align/pages/round-N.html`，告诉用户路径；所在环境能替他打开就打开。
- 所在环境里用户打不开本地文件时，用该环境给用户看文件的方式；实在不行，这一轮退回纯文字。

## 回传

回传是一段人能读懂的文本，用用户的语言。第一行固定为 `[frame-align] round N`，供核对轮次。每行以编号开头，编号与语言无关。

```
[frame-align] round 3
锚点：未改
理解：把"所有员工"改成"只有值班组成员"
p3-1 留着
p3-2 选：网页｜备注：不想等审核
p3-3 不对｜备注：那个文件是另一个项目的
p3-4 解释
d3-1 我来定
n2 重开｜备注：范围要再缩一点
整轮反馈：输出太多
展开过收起的内容：是
整体：流程部分想再多看几种做法
下一步：再来一轮
```

没有标记也没有备注的条目不必出现。

用户在对话里直接说的话，与回传同等对待。

### 通道一：粘贴（始终可用）

页面上有"复制结果"按钮，把上面的文本放进剪贴板；同时在页面上显示这段文本，以防复制失败。用户把它贴回对话。

### 通道二：自动回传（待实现）

skill 自带一个零依赖的小脚本起本地服务，页面提交时由它把回传写成文件，你去读取。脚本不可用或启动失败时，退回通道一。

这条通道尚未实现，其中两点未经验证：各种环境里能否稳定启动本地服务；提交之后你如何得知。

### 收到回传后

把原文存到 `returns/round-N.txt`。

核对第一行的轮次。与当前轮次不符，说明他提交的是一个旧页面：告诉他这一点，编号还对得上的标记和备注照常并入，对不上的列出来问他。不要把他已经写的内容整份作废。
