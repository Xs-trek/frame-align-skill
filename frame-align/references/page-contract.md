# 页面契约

页面是预制的：`assets/page.html`。它的样子和行为是固定的，所有模型下看起来一样。你不写 HTML，只写 `.frame-align/state.js`，页面把它显示出来。

## 为什么是页面

一是减轻用户的打字负担。能点选的不让他打字；点选表达不了的，旁边就有地方写。

二是页面的形状本身在起过滤作用。不同模型的输出风格差别很大，用"请简洁"这样的话去约束，效果不稳定。但标题、正文、详情各有各的位置和样式，需要他定的事单独成区，混在一起就摆不上去。

所以你要做的不是少写，而是把内容放进对的字段：一句话能说清的放 `title`，一两句的说明放 `text`，更长的论证、对比、步骤放 `detail`。页面负责让它们主次分明。

## 运行页面

每一轮写好状态之后，在前台运行页面命令，等它返回：

```
node <本 skill 目录>/scripts/serve.js <项目里的 .frame-align 目录>
```

它只为这一轮运行：替用户打开页面，等他提交，然后退出。不要放到后台。它最多等九分钟（`--wait 秒数` 可改），所以命令的等待时限设到十分钟，或所在环境允许的最长。

输出的第一行是 `frame-align page: http://127.0.0.1:端口/`。没有这一行就是没有运行（有的机器上命令存在却什么都不做，也不报错），换下一种方式再试：

```
python3 <本 skill 目录>/scripts/serve.py <项目里的 .frame-align 目录>
python  <本 skill 目录>/scripts/serve.py <项目里的 .frame-align 目录>
py -3   <本 skill 目录>/scripts/serve.py <项目里的 .frame-align 目录>
```

之后是两种结局之一：

- **`frame-align return: …`，后面是回传的全文。** 他提交了。回传已经存进 `returns/`，不必再读文件，直接往下做。
- **`frame-align: no return yet`。** 他还没提交，页面服务已经停了。告诉他一句：页面还开着，可以接着看和填，填完点提交，再回来说一声。然后停下。他回来后再运行一次同样的命令，页面会把他填好的内容自动交上来。

命令被所在环境中途终止或转到后台时，按第二种处理；它之后自己结束并带回了回传，就照第一种。

要点：

- **目录参数写项目里的 `.frame-align`**，拿不准当前目录就写绝对路径。它提示找不到 `state.js` 时，多半是目录给错了。
- **页面由命令替他打开。** 上一轮的页面还开着时，它会自己刷新到新一轮，通常不会再开一个。他说页面没有出现，就把第一行的地址给他，再运行一次。
- **再运行一次总是安全的。** 地址每次相同，上一次运行还没结束时新的一次会接替它。`.frame-align/server.json` 记着地址和页面凭据，不要改它。

### 两种运行时都没有

把 `assets/page.html` 复制到 `.frame-align/page.html`，让用户直接双击打开。它会读取同目录下的 `state.js`。此时页面无法自己写文件：浏览器支持时，提交按钮会弹出保存对话框，请他存到 `.frame-align/returns/`；不支持时退回为复制文本。他存好后回对话说一声，你去读那个文件。这是退路，能运行页面命令就不要走这条。

所在环境里用户打不开本地地址或本地文件时，用该环境给用户看页面的方式；实在不行，这一轮退回纯文字。

## 页面把状态显示成什么

有内容的才出现，所以页面随框架长大，首页最轻。

| 页面上 | 来自状态里的 | 说明 |
|---|---|---|
| 你的目标 | `anchor` | 始终在最上。他可以改 |
| 本轮在做什么 | `this_round` | 一两句 |
| 我的理解 | `understanding` | `show_understanding` 为真时完整展开、可改写；为假时折成一行 |
| 你的技术背景 | 第 1 轮自动出现；`background_options` 给出可点选的经历 | 可不填 |
| 需要你定的 | `kind` 为 `decision` 的提议 | 排在最前。选项成排显示，推荐项带标记 |
| 我告诉你的 | 其余提议 | 看法、灵感、事实、解释 |
| 还有 N 条没展开 | `shown` 为假的提议 | 他展开过会记进回传 |
| 我先定了的 | `delegated` | 短清单，每条可收回 |
| 框架现状 | `nodes` | 状态分布条加节点格子；点开看内容，可备注、可重开 |
| 这一轮整体怎么样 | 固定 | 六个可不选的选项、一个文本框、下一步。第 1 轮只有文本框 |
| 关于你的观察记录 | `observations` | 折叠，可编辑 |

卡片上不显示动作和性质的名称。他不需要知道一条内容在你的分类里叫什么，只需要知道要他做什么。

### 文字的格式

`text`、`detail`、节点的 `body`、`understanding`、`this_round` 支持少量格式：空行分段、`**加粗**`、`*强调*`、行内代码、以 `-` 或 `1.` 开头的列表、用竖线写的表格、用三个反引号围起来的代码块。对比和取舍优先写成表格，步骤写成列表，比整段文字好读。目录树、字符画这类靠对齐的内容放进代码块，否则会对不齐。

`detail` 超过一定高度会收起一部分，他点一下展开。内容不会丢，放心写全。

### 图

一张图比一段话清楚的时候，就画。提议、说明块（`note`）和节点都可以带一个 `figure` 字段，页面把它显示在正文下方。它接受两种内容：

- **SVG。** 以 `<svg` 开头。结构图、流程图、关系图这类静态的图首选它。给出 `viewBox`，或者同时给出宽和高。
- **一段 HTML。** 其他任何内容都按 HTML 处理，放进一个独立的框里显示，框的高度随内容变化。可以带自己的样式和脚本，所以用样式拼的条形图、用画布画的曲线都可以。

两种图都与页面隔离：图里的样式和脚本影响不到页面，也用不了页面的样式，需要什么自己写在图里。

图始终画在浅色的纸面上，深色主题下也是：用深色的线条和文字。

图只用来看：图里的按钮和输入不会进入回传。

## 组合由你决定

页面固定的只有外框和组件的样子：目标、本轮说明、整轮反馈、提交在外框里；卡片、对比表、步骤、框架图是组件。中间放什么、按什么顺序、用哪种组件，由你根据这个想法决定，写在状态的 `sections` 里。

不写 `sections` 时用默认排法：需要你定的、我告诉你的、我先定了的、框架现状。想法适合这个排法就不用写。

写了 `sections`，页面就按你给的顺序逐段显示。每一段是下面几种之一：

| 写法 | 显示成 |
|---|---|
| `{ "title": "…", "items": ["p3-1", "p3-2"] }` | 一组卡片，自上而下 |
| 同上，加 `"layout": "grid"` | 两列并排，适合几条简短、彼此平行的灵感 |
| 同上，加 `"layout": "steps"` | 带序号、有先后的步骤 |
| `{ "component": "note", "title": "…", "text": "…", "figure": "…" }` | 一块说明，不带标记。适合放你的定位、背景、一张总览图。`text` 可以省略，只放图 |
| `{ "component": "framework", "view": "tree" }` | 框架现状。`view` 省略时是格子；`tree` 按节点的 `parent` 缩进成层级 |
| `{ "component": "delegated" }` | 我先定了的清单 |

每段都可以带 `title` 和 `hint`（标题右侧的一句小字）。

需要他定的事有两种显示方式，由你给的数据决定：选项只带 `note` 时是并排的选项块；选项带 `points`（几个相同的比较维度）时是一张对比表，适合选项之间要逐项比较的情况。

几条规则：

- 没有被任何一段提到的提议不会丢，页面把它们按默认排法接在后面。
- 含有需要他定的事的那一段，标题会自动突出。把这样的段放在靠前的位置。
- 这些组件覆盖不了的呈现，用 `figure` 画出来，或者用 `detail` 里的表格、列表和代码块。自由发挥只在图的框里；页面本身的结构不要试图用 HTML 去改，那样页面就不再统一。

## 标记

页面按卡片的类型放出适用的标记。回传里写的是按钮上的文字，括号里是它对应的键。不标记是允许的，表示他对这条暂无意见。

| 卡片 | 怎样判定 | 可用标记 | 标记后的结果 |
|---|---|---|---|
| 灵感 | `move` 是 `diverge`，没有 `kind` | 留着（`keep`）、不要（`drop`）、多来点（`more`） | 留着：成为候选节点，状态为待定。多来点：下一轮沿这个方向 |
| 建议 | 没有 `kind` 的其他提议 | 接受（`accept`）、不接受（`reject`）、解释（`explain`）、去核实（`verify`） | 接受：并入框架。不接受：不并入，日志记一行 |
| 需要你定的事 | `kind` 是 `decision` | 各个选项（`choose`）、解释（`explain`）、去核实（`verify`） | 选中任一项：对应节点已确认 |
| 事实 | `kind` 是 `fact` | 不对（`wrong`）、去核实（`verify`）、解释（`explain`） | 复核后报告。复核后仍各执一词：有分歧 |
| 解释 | `move` 是 `explain` | 还是没懂（`explain`） | 换一种说法再讲 |
| 我先定了的 | `delegated` 里的条目 | 我来定（`take_over`） | 转成需要你定的事 |
| 框架现状里的节点 | 已确认的节点 | 重开（`reopen`） | 已确认变回待定，记入日志 |

每张卡和每个节点都带备注框。标记只负责便宜的决定，真正改变方向的内容多半出现在备注里。

## 整轮反馈

在页面底部，可多选，可不选。选了就记入观察记录，并据此调整下一轮。

| 选项 | 键 | 下一轮怎么调 |
|---|---|---|
| 输出太多 | `too_much` | 减量，收起更多，正文更短 |
| 输出太少 | `too_little` | 多展开几条，讲得细一些 |
| 太难懂 | `too_hard` | 换说法，少用术语，把选择讲成后果 |
| 跑偏了 | `off_track` | 对照锚点，告诉他你认为偏在哪，按他的备注拉回 |
| 进度太慢 | `too_slow` | 每轮推进更多：多替他定小事，把相关的决定合并，少发散，主动建议收敛 |
| 进度太快 | `too_fast` | 放慢：少并入，回到他还没想清的地方，多给解释 |

## 回传

用户点提交后，结果被写到 `.frame-align/returns/round-N.txt`，同时由页面命令打印给你。同一轮重复提交，以最后一次为准。

回传不经过对话，不要请他把页面内容贴给你。

回传是一段人能读懂的文本，用页面的语言。第一行固定为 `[frame-align] round N`。每行以编号开头，编号与语言无关。

```
[frame-align] round 3
锚点：未改
理解：把"所有员工"改成"只有值班组成员"
p3-1 选：网页、解释
p3-2 不对｜备注：那个文件是另一个项目的
p3-4 留着、多来点
d3-1 我来定
n2 重开｜备注：范围要再缩一点
整轮反馈：输出太多、进度太慢
展开过收起的内容：是
整体：流程部分想再多看几种做法
下一步：再来一轮
```

没有标记也没有备注的条目不会出现。"下一步"是三者之一：再来一轮、灵感够了、框架成立；第 1 轮没有这一行，按再来一轮处理。

### 读回传时

核对第一行的轮次。与当前轮次不符，说明他提交的是一个旧页面：告诉他这一点，编号还对得上的标记和备注照常并入，对不上的列出来问他。不要把他已经写的内容整份作废。

他说已经提交、而你没有收到回传：再运行一次，已经存下的和还没送达的回传都会交上来。

## 页面的语言

状态里的 `lang` 写 `zh` 或 `en`，页面用内置的对应文字。其他语言写它的语言代码，并在 `labels` 里提供要替换的界面文字；没提供的部分显示英文。
