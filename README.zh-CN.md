# frame-align

[English](README.md) | **简体中文**

> 先对齐框架，再动手。

`frame-align` 是一个 agent skill，面向能读写文件的编码 agent。在写任何产品代码之前，agent 和用户通过一个可交互的 HTML 页面反复对齐，直到用户认为这个想法的框架成立。agent 用自己的话复述它的理解，提供方向，指出空缺与矛盾，定位难题的关键点；用户用点选和备注回应。

衡量它的标准只有一个：用户是否比不用它时更轻松地完成了对齐。

## 现状

早期设计稿。

- skill 的指令已经写完。
- 还没有完整运行过。这里的全部内容都是未经验证的设计。
- 页面模板和自动回传通道尚未实现。目前由 agent 每轮生成一个单文件 HTML 页面，用户把结果粘贴回对话。

skill 的指令用中文写成。页面跟随用户使用的语言。

## 为什么

用户带着一个软件想法来的时候，立刻开始实现，往往做出一个双方都以为对方理解了的东西。常见的补救是一长串澄清问题，这又把工作量转到了用户身上。

`frame-align` 想同时避开两种失败：

- **过重**：流程和格式把 agent 框死，不同的想法得到雷同的问题，agent 自己的洞察出不来。
- **过轻**：agent 跳过对齐，或者页面只是把平常的回答换了个皮。

它的办法是固定循环的形状，把循环里的内容留给 agent。一切从轻开始，轻的手段用过仍不够时才加重。

## 它怎么工作

1. **先读后问。** agent 先读它自己能读到的东西，再用自己的话复述用户的需求。
2. **一轮。** agent 探索，把状态写入 `.frame-align/state.json`，生成页面。用户点选标记、写备注、提交。agent 调整，进入下一轮。
3. **出口。** 框架是否成立由用户决定。先做一次简短的出口检查，列出尚未了结的内容，然后 agent 写出框架文档，默认是 `framework/framework.md`。
4. **回炉。** 框架不会在出口处冻结。实现暴露出框架没预料到的东西时，再次调用 skill，从待回炉记录接着走。

skill 只管框架循环和回炉，不管实现阶段。

### 页面上

- 用户的原话钉在最上，作为目标。只有用户能改。
- 内容按"要用户做什么"分开摆：需要你定的、我告诉你的、我先替你定了的小事。最后一类每条都能收回。
- 每张卡带适用的标记和备注框。标记负责便宜的决定，真正改变方向的内容写在备注里。
- 一排可不选的整轮反馈：输出太多、输出太少、太难懂、跑偏了、进度太慢、进度太快。
- 页面随框架长大，首页最轻。

### 预设

预设在第一轮定方向，那时 agent 对用户了解最少。反馈越多，预设管得越少。

| 预设 | 用户带来的 | 第一轮 |
|---|---|---|
| 种子 | 一句话，或一个模糊的点子 | 复述，给几条方向。暂不质疑 |
| 骨架 | 整体框架有了，很多地方是空的 | 复述，画出骨架，标出空缺 |
| 体检 | 相对完整的草案 | 复述，再指出最要紧的一两处矛盾或风险 |
| 难点 | 一个卡住的问题 | 复述，说出最可能的关键点和依据，给出最能区分各种可能的那一步验证。不铺开试验矩阵 |

### 把决定权留在用户手里

用户同意 agent 不是问题，用户不再做决定才是。输出长到读不下去、一连串看起来专业的内容被一路放行、agent 定了用户没看见的事，都会造成这种情况。

skill 首先把它当作 agent 输出的问题：少给，把需要决定的和不需要的分开，说用户能判断的话。轻的手段都不管用时，才请用户先说自己的倾向，再看推荐。

它也要求 agent 不讨好、不免责：事实和看法分开；被质疑时去复核，而不是让步或坚持；给出明确的推荐；去核实，而不是加免责声明。

## 安装

把 `frame-align/` 文件夹复制到你的 agent 的 skills 目录。

- **Claude Code**：`~/.claude/skills/frame-align/` 对所有项目生效，或放在某个项目的 `.claude/skills/frame-align/` 下。用 `/frame-align` 调用。
- **其他支持 Agent Skills 的 agent**：放到该 agent 的 skills 目录，按它点名调用 skill 的方式使用。

这个 skill 设计为手动调用。

- `SKILL.md` 带有 `disable-model-invocation: true`，Claude Code 和 Cursor 认这个字段。上传到 claude.ai 或为 Skills API 打包之前要删掉这一行，那里不接受未知的 frontmatter 字段。
- `agents/openai.yaml` 为 Codex 设置了 `allow_implicit_invocation: false`。写法依据 Codex 文档，没有在 Codex 里实测。
- Gemini CLI 没有仅手动的开关，在那里只能靠 description 里的那句话。
